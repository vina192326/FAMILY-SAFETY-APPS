# Parent Mode implementation status

## Source design
The approved Stitch source contains the Parent navigation tabs Home, Devices, Activity, Alerts and Settings, plus Child Profile, Pair Device, Location & Safe Places, Reports, Settings Hub and Account & Security screens. Its Home render includes family overview, children cards, View Map, Ring, Pause, Locate, Nudge, History, Add Child, Link Device, Check-In and Downtime actions. Settings Hub includes Security, Family, Routines, Privacy & Knox categories, data retention, export, deletion, language, theme, permission health, updates and support.

Latest user requirements override the old source flow: Parent must open directly without login, email, username or password. Pairing OTP is entered by Parent after being generated by the Kids app.

## Android files added
- Root Android Gradle project: `settings.gradle.kts`, `build.gradle.kts`, `gradle.properties`
- One Android app module: `app/build.gradle.kts`, `app/src/main/AndroidManifest.xml`
- Compose navigation shell with five Parent tabs and visible empty/offline states.
- Parent device bootstrap API client; bearer token is encrypted using Android Keystore AES-GCM.
- Device list, history list, immediate history delete and PDF-before-delete preference API calls.
- Settings groups and search; PDF preference switch.
- CI workflow `.github/workflows/android.yml` to assemble a debug APK and upload it as a workflow artifact.

## Implemented in this first Android foundation
- One Android app module and Parent tab navigation.
- Parent no-account/no-password entry (device bootstrap).
- Explicit offline/error states; no fabricated child telemetry.
- Device list from existing backend.
- History read/delete and PDF preference API wiring.
- Parent settings categories as navigation placeholders.

## Not yet implemented / not verified
This is not yet the complete Parent dashboard. The following are still required:
- Exact visual parity with the Stitch renders (current Compose is a functional starter layout, not pixel-matched).
- Real child profile CRUD and profile-specific settings.
- Parent OTP validation -> plan selection -> Razorpay checkout -> verified Permit issuance flow in Android UI.
- Dedicated 20-row Permission Centre with real Kids-device permission snapshots, request/approval flow and Android Settings guidance; separate Family Data Dashboard for live/last-known/history feeds (see `docs/PARENT_PERMISSION_AND_LIVE_DATA_DASHBOARD.md`).\n- Devices: real diagnostics, ping, unlink/revoke, wearable pairing, integrity checks and battery optimization help.
- Location map, live routes, geofence create/edit, safe places, check-in, ring/pause/nudge commands.
- Activity charts, app usage and screen-time controls, routines, +15m bonus and pause-all endpoints.
- Alert feed, SOS push delivery, severity filters, reminder, route tracking and quiet-hours configuration.
- PDF generation, CSV export, Android Downloads/Share Sheet, per-item download/share and background local-cache expiry.
- Settings persistence and real APIs for guardian roles, timezone, routines, notifications, language/theme, permission health, updates, support/legal, data export, account deletion and AI opt-out.
- Native permission rationale/request screens and policy review for every sensitive Android permission.
- Backend APIs and database models for the above feature groups; push notification registration and event ingestion.
- Android unit/UI tests, backend integration tests, emulator and physical-device tests, release signing, install/upgrade testing and production configuration.

## Acceptance gate
Do not declare Parent Mode complete until all Stitch Parent screens and all mapped Parent controls have real behavior, all permissions are correctly requested and tested, API/database/payment flows pass integration tests, and the release APK passes emulator and physical-device end-to-end tests.
